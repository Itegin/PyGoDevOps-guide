# roadmap-site

Личный сайт-трекер для гайда «Python + Go → DevOps»: список фаз/уроков с чекбоксами,
прогресс сохраняется в SQLite. Работает и локально, и в Docker на домашнем сервере.

**Стек:** Flask (Python) + SQLite + Jinja2-шаблоны + чуть-чуть ванильного JS.
Без фреймворков на фронте специально — сайт личный, задача не в красоте,
а в том, чтобы было удобно отмечать прогресс с телефона и с ноутбука.

---

## 1. Быстрая проверка локально (без Docker)

Полезно, чтобы убедиться, что всё работает, прежде чем тащить на сервер.

```bash
cd roadmap-site
python3 -m venv venv          # изолированное окружение — не трогает системный Python
. venv/bin/activate           # активировать venv (в Windows: venv\Scripts\activate)
pip install -r requirements.txt
python app.py
```

Открой `http://127.0.0.1:5000` в браузере. Останови сервер `Ctrl+C`, когда закончишь.

## 2. Деплой на домашний Debian-сервер (основной сценарий)

### 2.1 Скопировать проект на сервер

Проще всего через `git` (заодно у тебя будет отдельный репозиторий для портфолио):

```bash
# на сервере
git clone <URL-твоего-репозитория> roadmap-site
cd roadmap-site
```

Либо, если репозитория пока нет — просто скопировать папку по SSH:

```bash
# с локальной машины
scp -r roadmap-site your-user@server-ip:~/roadmap-site
```

### 2.2 Убедиться, что Docker установлен

```bash
docker --version
docker compose version
```

Если команды не найдены — ставим Docker Engine по официальной инструкции
(`https://docs.docker.com/engine/install/debian/`), в этом плане ты и так
скоро столкнёшься с Docker в первых проектах гайда.

### 2.3 Собрать и запустить

```bash
cd ~/roadmap-site
docker compose up -d --build
```

Разбор команды: `up` поднимает сервисы из `docker-compose.yml`, `-d` — в фоне
(detached, чтобы не занимать терминал), `--build` — пересобрать образ по
свежему Dockerfile (нужно при первом запуске и после изменений в коде).

### 2.4 Проверить, что всё поднялось

```bash
docker compose ps                 # статус контейнера, должен быть "healthy"
docker compose logs -f roadmap    # логи в реальном времени, Ctrl+C чтобы выйти
curl http://127.0.0.1:8080/healthz
```

Ожидаемый ответ: `{"status": "ok"}`.

## 3. Доступ из локальной сети (LAN)

Узнай IP сервера в локалке:

```bash
ip a | grep "inet " | grep -v 127.0.0.1
```

С любого устройства в той же Wi-Fi/локальной сети открой в браузере:

```
http://<IP-сервера>:8080
```

Например `http://192.168.1.50:8080`. Это уже полностью рабочий вариант —
дальше всё опционально.

### Автозапуск после перезагрузки сервера

`restart: unless-stopped` в `docker-compose.yml` уже говорит Docker
перезапускать контейнер, если он упал. Чтобы контейнер поднимался и после
перезагрузки самого сервера, убедись, что служба Docker включена в автозапуск:

```bash
sudo systemctl enable docker
```

## 4. (Опционально) Внешний доступ через твой домен на DuckDNS + HTTPS

Нужно, только если хочешь открывать сайт не из дома. Для чисто личного
чек-листа это не обязательно — но раз домен уже есть, вот как это сделать
аккуратно, с настоящим HTTPS через Let's Encrypt и через Caddy (простой
реверс-прокси с автоматическим TLS, буквально пара строк конфига).

**Важно про безопасность:** приложение само по себе без авторизации —
кто угодно с твоим URL сможет отмечать/сбрасывать твой прогресс. Для
чисто личного чек-листа это не катастрофа, но раз сайт станет доступен
из интернета — ниже добавлена базовая HTTP-авторизация (`basic_auth`).

### 4.1 Обновление IP в DuckDNS (если IP от провайдера динамический)

```bash
mkdir -p ~/duckdns && cd ~/duckdns
cat <<'EOF' > duck.sh
echo url="https://www.duckdns.org/update?domains=ТВОЙ_ПОДДОМЕН&token=ТВОЙ_ТОКЕН&ip=" | curl -k -o ~/duckdns/duck.log -K -
EOF
chmod 700 duck.sh
# добавляем в cron: обновлять IP каждые 5 минут
(crontab -l 2>/dev/null; echo "*/5 * * * * ~/duckdns/duck.sh >/dev/null 2>&1") | crontab -
```

Замени `ТВОЙ_ПОДДОМЕН` и `ТВОЙ_ТОКЕН` на свои — оба берутся на duckdns.org
в личном кабинете.

### 4.2 Проброс портов на роутере

На роутере пробрасываем **80** и **443** (TCP) на локальный IP сервера —
без этого Let's Encrypt не сможет подтвердить, что домен действительно
указывает на твой сервер, и не выдаст сертификат.

### 4.3 Добавить Caddy как ещё один сервис в docker-compose.yml

```yaml
services:
  roadmap:
    build: .
    container_name: roadmap-site
    restart: unless-stopped
    expose:
      - "5000"          # больше не публикуем 8080 наружу напрямую — только для Caddy
    volumes:
      - progress-data:/app/db

  caddy:
    image: caddy:2-alpine
    container_name: roadmap-caddy
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy-data:/data      # тут Caddy хранит выпущенные сертификаты

volumes:
  progress-data:
  caddy-data:
```

### 4.4 Сгенерировать хэш пароля и создать Caddyfile

```bash
docker run --rm caddy:2-alpine caddy hash-password
# вставь свой пароль, скрипт вернёт длинную bcrypt-строку — сохрани её
```

Файл `Caddyfile` рядом с `docker-compose.yml`:

```
твой-поддомен.duckdns.org {
    basic_auth {
        admin ВСТАВЬ_СЮДА_BCRYPT_ХЭШ
    }
    reverse_proxy roadmap:5000
}
```

Caddy сам выпустит и продлит сертификат Let's Encrypt, как только увидит
в конфиге доменное имя — дополнительно ничего настраивать не нужно.

```bash
docker compose up -d --build
```

Теперь сайт доступен как `https://твой-поддомен.duckdns.org`
(логин `admin`, пароль — тот, что ты ввёл при хэшировании).

## 5. Как редактировать содержимое гайда

Весь текст (фазы, уроки, описания) — в `data/lessons_data.py`, обычные
Python-словари, без БД и без магии. Чтобы добавить урок:

1. Открой `data/lessons_data.py`.
2. Найди нужную фазу в списке `PHASES`.
3. Добавь новый словарь в её `"lessons"` со **своим уникальным** `"id"`.
4. Перезапусти: `docker compose up -d --build` — новый урок появится
   со статусом «не выполнено», старый прогресс не потеряется (он привязан
   к `id`, а не к порядку в списке).

## 6. Бэкап прогресса

Прогресс лежит в volume `progress-data` в виде файла SQLite. Быстрый бэкап:

```bash
docker compose cp roadmap:/app/db/progress.db ./progress-backup.db
```

Короткое описание, которое можно адаптировать под резюме/README на GitHub:

> Личный сервис-трекер учебного плана: Flask + SQLite + Docker, задеплоен
